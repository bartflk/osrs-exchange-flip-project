# CLAUDE VISION & BRAINSTORM BLUEPRINT
## Long-Term Technical Vision for the OSRS Flip Assistant

---

# Purpose

This document is the long-term vision and design specification for the project.

It is NOT a task list.

It is NOT a sprint backlog.

It exists so that every future implementation follows the same philosophy and architecture.

Whenever planning or implementing features:

1. Read this document.
2. Inspect the existing implementation.
3. Search for reusable components.
4. Do not duplicate systems.
5. Keep deterministic calculations separate from AI reasoning.

The goal is NOT to build another GE flip finder.

The goal is to build the best OSRS Decision Engine.

---

# Overall Philosophy

The project consists of three layers.

```
                DATA

                  ↓

      Deterministic Quantitative Engine

                  ↓

         Machine Learning Models

                  ↓

        Claude Reasoning & Explanation

                  ↓

               User
```

Important:

Claude never replaces mathematics.

Claude never invents numbers.

Claude never becomes the source of truth.

Claude explains.

Claude reasons.

Claude critiques.

Claude summarises.

The Quant Engine owns calculations.

ML owns probabilities.

Claude owns communication.

# Forecasting System

Forecasting is independent from recommendations.

Its purpose is predicting future market behaviour.

Supported horizons:

5 minutes

15 minutes

30 minutes

1 hour

2 hours

6 hours

12 hours

Each horizon represents a different user trading strategy.

## Forecast Outputs

The forecasting model should predict:

Future Low

Future High

Future Spread

Future Volatility

Expected Holding Time

Expected Fill Time

Expected Profit Distribution

Do NOT predict only one value.

Predict distributions.

# Prediction Bands

Prediction bands should represent uncertainty.

Rather than:

Predict:

Q10

Q25

Q50

Q75
